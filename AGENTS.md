When changing IDs, migrations, persistence, or import/export flows, prefer stable client-generated IDs, append-only migrations, and repository boundaries that can later support cloud restore or sync without making the workout UI depend on the network.
- [2026-06-22] Agent-operable iOS app: A core tenant of the iOS app is that agents must be able to fully control and use it in both Simulator and iPhone Mirroring. - [2026-07-11] Better Auth database rate-limit schema: Better Auth 1.6.20 injects a generated `id` into every adapter model, including `rateLimit`. When using Prisma with Turso/libSQL database-backed rate limiting, keep `RateLimit.id` as the primary key, `RateLimit.key` unique, and `lastRequest` as `Float`: Better Auth sends epoch milliseconds as a JS number, which libSQL binds as SQLite `REAL`, while Prisma `BigInt` rejects the returned value. Using `key` as the primary key or `BigInt` for this Turso path makes OTP/session requests fail.
- [2026-07-11] Turso Sync schema provisioning: Turso Sync replicates row changes but does not copy client-created DDL into an empty per-user remote database. Keep local-first migrations shared between mobile and server, and migrate the remote database before returning sync credentials; otherwise the first pull can replace the phone's local schema with the blank remote schema.
- [2026-07-10] Turso React Native transaction control: In `@tursodatabase/sync-react-native@0.6.1`, `Database.run("BEGIN")` does not retain an active transaction through later `run()` calls; the writes autocommit and `COMMIT` fails with `cannot commit - no transaction is active`. Do not issue manual transaction-control statements through `run()` or use the SDK transaction helper in this version. Keep multi-write operations behind `withLocalTransaction()` so true transactions can be restored after the SDK fixes this behavior.
- [2026-07-10] Turso React Native statements and transactions: `@tursodatabase/sync-react-native@0.6.1` failed on valid single-statement DDL through `Database.exec()` with `near ")": syntax error`; its `transaction()` helper also uses `exec()` and can commit successfully before reporting a false rollback error. Use individual delimiter-free `Database.run()` calls and the app's `withLocalTransaction()` helper, then verify a fresh Simulator install before shipping.

Keep only the target simulator booted, restart the pinned mirror after native builds, and wait for a fresh `live` frame between gestures when browser-operating the app.
